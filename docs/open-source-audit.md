## Causality hazards found in upstream source

[SMC source](https://github.com/joshyattridge/smart-money-concepts/blob/master/smartmoneyconcepts/smc.py) uses future-shifted windows for centered swings. A pivot becomes known only after its right-hand confirmation bars close. Its FVG annotation references the next candle and requires at least that candle's close before publication. `MitigatedIndex`, `BrokenIndex`, and swept-liquidity endpoints scan later bars; order blocks can be written onto earlier candle rows with volume learned at a later break. Full-sample liquidity ranges also depend on future extremes. Exposing those annotations at their original row time would leak information. Correct integration would need separate occurrence/confirmation times, prefix-invariance tests, and an incremental event ledger. That adapter remains deferred.

The [0.0.26 source distribution](https://pypi.org/project/smartmoneyconcepts/0.0.26/#files) contains `pandas==2.0.2`, `numpy==1.24.3`, and `numba==0.58.1` in `setup.py`. Those historical pins are unsuitable as mandatory dependencies for this Python 3.12/3.13 stack. The 0.0.27 metadata loosens the requirements but does not remove the causality hazards. Neither version is installed by `requirements-analytics.txt`.

[MarketProfile source](https://github.com/bfolkens/py-market-profile/blob/master/src/market_profile/__init__.py) rounds each bar's **close** to a row and sums its entire bar volume there. That is a close-binned OHLCV profile, not executed volume-at-price or an order book. Tick size, quote/base volume units, slice boundaries, and session/timezone choices matter. Any future adapter must slice only observations available at the decision time; a whole-window profile must never be backfilled into past decisions.

`ruptures` is expressly an [offline change-point library](https://pypi.org/project/ruptures/). Its retrospective normalization and segmentation can change when future observations arrive. Report change points are labeled **RETROSPECTIVE ONLY**. The mandatory terminal segment marker is omitted. River instead receives one bounded absolute log return at a time: `min(abs(return)/0.05, 1)`, with the 5% scale fixed before observing the series. No fitted full-sample scale enters ADWIN. Neither adapter changes any trade.

## Binance access and data rights

The official [market-data-only documentation](https://developers.binance.com/docs/binance-spot-api-docs/faqs/market_data_only) explicitly supports unauthenticated `/api/v3/time` and `/api/v3/klines` on `data-api.binance.vision`. The CLI uses only those two endpoints. REST timestamps default to milliseconds. The [archive README](https://github.com/binance/binance-public-data#data-information) separately says spot archive timestamps from 2025 onward are microseconds and archive files can be revised; mixing those units is unsafe. No archive reader is implemented.

The current [Binance Vision Dataset Terms](https://github.com/binance/binance-public-data/blob/master/TERMS_AND_CONDITIONS.md), version 1.0 updated **2026-08-26**, specify **CC BY-NC-SA 4.0** for the covered datasets, noncommercial use, attribution/share-alike derivatives, and a separate written enterprise license for commercial use. An old README MIT label must not be presented as permission to commercially redistribute the data. The terms describe `data.binance.vision` and associated endpoints; their precise application to a particular REST deployment is not independently adjudicated here. The implementation is research-oriented and does not assert a commercial data license. Monetization requires checking the applicable Binance agreement.

Following the official [IP-limit rules](https://developers.binance.com/docs/binance-spot-api-docs/rest-api/limits), each request has a 12-second timeout and at most three attempts. HTTP 429 honors `Retry-After` when within the 20-second per-wait budget; longer waits abort the run. HTTP 418, regional restrictions, and permanent errors fail without host switching. Pagination is capped and advances backward by exchange timestamps. The live candle, gaps, duplicate/out-of-order rows, impossible OHLC, nonfinite prices, and stale data are rejected. Existing output survives a failed download.

## Reproducible comparison and report conventions

The standard-library core is mandatory and deterministic. Two fixed long-only spot rules use only information available at a 1H close and the most recent **already closed** 4H candle:

- **EMA 21/50 + RSI momentum:** close > EMA21 > EMA50, RSI14 in [50,68], and 4H close > 4H EMA21. Exit signal: close < EMA21 or RSI <45. Initial stop is 2 ATR14 below the decision close; target is twice that risk above it.
- **EMA 50 + RSI pullback:** close > EMA50, RSI crosses upward through 40, and the same 4H trend confirmation. Exit signal: close < EMA50 or RSI >=65. Stop is 1.5 ATR14 below the decision close; target is twice that risk above it.

EMA uses an initial SMA seed, RSI/ATR use Wilder smoothing, and a flat RSI series is 50. The first 200 hourly bars warm up indicators. Half of the remaining observations initialize training; the rest form three disjoint chronological test blocks with expanding earlier training windows. Parameters are not tuned on either partition. Each fold resets positions; training starts with normalized cash 1000, while test cash compounds sequentially across folds.

A close-t decision can first fill at open t+1. An opening price outside the prior stop/target bracket cancels entry. Only one all-cash, unlevered position exists; quantity includes the entry fee. Every side charges 10 bps fee and 5 bps adverse slippage. Stops win ambiguous OHLC bars, gaps through stops use the lower open, and target fills receive no favorable gap windfall. Entry-bar targets are skipped while stops remain active. Signal exits and the 72-hour time exit use the next open. Known fold boundaries flatten at the final bar's open, with exit costs. No signal receives an optimistic same-close fill.

The output matches `lib/types.ts` **AnalyticsReport** exactly. Additional diagnostics and fold boundaries live in `notes`, not invented schema fields. `totalReturn`, `testReturn`, trade statistics, and equity describe concatenated **out-of-sample** folds. `trainReturn` is the arithmetic mean of overlapping expanding-training returns; it is never compounded across those overlapping windows. Equity begins at 1000. Returns, expectancy, drawdown, and win rate use percentage points; profit factor is the ratio of summed net cash gains to absolute net cash losses. Expectancy is mean net trade return. Undefined values are JSON `null`, never NaN/Infinity.

`overfitWarning` is true for fewer than 30 OOS trades or descriptive train-to-test degradation. It is not a statistical proof about overfitting. Current regime is a causal EMA label. Optional drift absence is explicitly identified as unavailable instead of being portrayed as an evaluated negative. Drawdown measures hourly liquidation-cost-adjusted equity, not the unobserved intrabar path. Fractional quantities do not apply exchange lot/tick/minimum-notional rules; this comparison is not executable position sizing. Short single-symbol samples, fixed slippage, survivorship/selection effects, and upstream revisions limit conclusions.

## Run and verify

```powershell
python -m unittest discover -s tests/python -v
python -m analytics.run --symbol BTCUSDT --output data/analytics.json --limit 1000
python -m analytics.run --symbol BTCUSDT --output data/analytics.json --limit 1000 --as-of 2026-10-15T07:00:00Z
python -m pip install -r requirements-analytics.txt
```

Use `--no-optional` for a strictly standard-library run. Each CLI output records the exact `--as-of` cutoff and candle limit needed for a later rerun. Use that recorded cutoff rather than the last candle's inclusive close timestamp. Data revisions can still alter subsequent downloads. Default requests are 1000 1H and 350 4H candles; the maximum is 3000 + 850 candles. No raw candle files are persisted and the compact report is written atomically. The normal output belongs in ignored `data/` or the durable market-data state, not source history.

Pinned optional versions are in `requirements-analytics.txt`. NumPy 2.2.6, pandas 2.2.3, and SciPy 1.15.3 form the tested shared stack rather than unconstrained latest numerical packages. Top-level versions are pinned; transitive dependencies are not a complete lock file. Primary PyPI metadata confirms the declared interpreter ranges and 3.12/3.13 wheels. Actual isolated **Python 3.13 Windows** installation and all 33 tests passed, including all four optional adapters. A **Python 3.12 Linux** wheel-only resolver check passed for manylinux2014 plus manylinux_2_28; 3.12 runtime execution remains the CI's check. Python 3.14 is excluded by the pinned ruptures release.

TDD evidence: the initial 22 simulator/data/report tests failed before implementation; the optional/CLI tests then failed before their implementation. The final 33-test suite covers future-price/prefix invariance, closed 4H alignment, chronological folds, exact schema, fee/slippage cash conservation, stop gaps, ambiguous stop/target bars, no optimistic entry-bar target, no overlap, equity drawdown, retry bounds, atomic failure preservation, reproducible cutoff, and optional absence. Deterministic synthetic fixtures exist only in tests.

A real 1000-hour BTCUSDT verification ended at **2026-10-15T06:59:59.999Z**. Momentum produced 22 OOS trades and **-9.768%** net return; pullback produced zero OOS trades and 0%. Both were flagged for low sample. Optional and core strategy arrays were identical. The native pandas-ta-classic EMA/RSI checks passed; QuantStats reproduced 9.768% hourly drawdown. This is observed verification output, not a claimed profitable strategy or fabricated trading history.
